## 2. なぜ

- いまは申請のたびに Word/Excel の様式を開いて、自社の住所・代表者・担当者・現場・期間を手で書き直している。その結果、住所の番地違い・宛先の取り違え・「日」抜けなどの間違いが様式に残っている（設計書 §2.3）。
- 申請者の欄は自社情報、現場と期間は案件から入れられる。土台（申請のデータ）を先に作っておけば、Phase 2 の図面で計算した占用面積をそのまま申請書の「数量」に流し込める。

## 5. API

すべて admin・manager だけ。`lib/api/utils.ts` の `requireManagerOrAbove` を使う（ログイン時に `lib/auth.ts` でロールが小文字にそろえられているので、そのまま使ってよい。自社班の出来高 `app/api/own-crew-volume/route.ts` と同じ）。

| メソッド | パス | 中身 |
|---|---|---|
| GET | `/api/road-permits` | 一覧（`deletedAt` が空のもの）。絞り込み: `status`・`projectMasterId`。自社情報（`CompanyInfo`）と「前回の担当者・現場責任者」も一緒に返す |

| PUT | `/api/road-permits/[id]` | 保存（`values`・`documents`・`status`・`title`） |
| DELETE | `/api/road-permits/[id]` | 論理削除（`deletedAt` を入れる） |

## 7. 入力値（`values`）の形と自動入力

形は Claude Code が決めてよいが、次の欄を必ず持つこと。型は `types/roadPermit.ts`、既定値の組み立ては `lib/roadPermit/defaults.ts`（テストを書く）。

| まとまり | 欄 | 初期値の取り出し元 |
|---|---|---|
| 申請者 | 郵便番号・住所・会社名・代表者の肩書と氏名・電話 | 自社情報（`CompanyInfo` の postalCode / address / name / representativeTitle / representative / tel） |
| 担当者 | 氏名・連絡先 | 前回の申請の値（無ければ自社情報の `contactPerson`・連絡先は空） |
| 現場責任者（警察） | 住所・氏名・電話 | 前回の申請の値（無ければ空） |
| 現場 | 場所（地番まで）・案件名 | 案件の `location`（無ければ prefecture＋city）・`title` |
| 期間 | 工事期間（から／まで）・占用（使用）期間（から／まで）・時間（から／まで） | 案件の `scheduledStartDate` / `scheduledEndDate`。時間は 9:00〜17:00 |
| 道路 | 路線名・車道／歩道／その他・舗装道／砂利道・住宅地図のページ | 空 |
| 占用物件 | 目的・名称・構造・規模・数量（㎡）・面積の表記・工事実施の方法・道路の復旧方法 | 目的「建物改修工事に伴う足場設置」・名称「足場」・構造「鋼製足場」・方法「請負」（前回の値があれば前回） |
| 警察 | 宛先の警察署名・道路使用の目的・場所又は区間・方法又は形態・添付書類・条件欄の文言 | 宛先「松山東警察署長」・添付書類「位置図・現地写真・平面図（保安図）」・条件欄「別紙の通り」（今の様式に印字されているため。§14） |
| 松山市 | 宛名（市長名）・許可申請／協議・新規／変更・第32条／第35条・変更時の従前の許可番号と年月日・添付書類 | 宛名「松山市長　野志　克仁」・許可申請・新規・第32条・添付書類「ア.警察署長の道路使用許可書の写　イ.位置図・平面図・断面図・立面図・外　ウ.着工前写真」 |

- 申請者の欄も**申請ごとに上書きできる**ようにする（自社情報の値は初期値として入れるだけ）。
- 宛名（警察署名・市長名）は人や部署で変わるので、画面で直せる文字にする（様式カタログの値は初期値）。

## 8. PDF（3 様式）

- 作り: `@react-pdf/renderer`（既存の帳票と同じ。フォントは `components/pdf/styles.ts` の NotoSansJP）。A4 縦。
- 置き場所: `components/pdf/roadPermit/`（様式ごとに 1 ファイル）＋ `utils/roadPermitPdf.tsx`（Blob を作る・ダウンロード。`utils/joyoStatementPdf.tsx` と同じ形）。
- 様式の一覧（カタログ）: `lib/roadPermit/forms/`（1 様式 1 ファイル＋一覧の `index.ts`。id・名前・申請先・宛名の初期値・使う欄・添付書類の文言）。Phase 4 で様式を足すときは、ここに 1 ファイル足すだけで済む形にする。
- **見た目は原本（`docs/road-permit/forms/`）に合わせる。** 罫線の位置・欄の並び・文言・備考欄まで同じにする。原本に無い飾りは足さない。
- 1 つの PDF に、選んだ様式を順に入れる（例: ① → ② → ③）。

### 8.1 ① 道路使用許可申請書（警察・別記様式第六）

上半分が申請、下半分は警察が書く許可証の欄（空欄のまま印刷）。

| 様式の欄 | 入れる値 |
|---|---|
| 左上「県収入証紙」の枠 | 枠だけ |
| 日付 | 申請日（令和○年○月○日。未定なら「令和　年　月　日」と空けて印刷） |
| 宛先 | 「○○警察署長　殿」 |
| 住所／申請者／氏名 | 申請者の住所／会社名／代表者の肩書と氏名 |
| 道路使用の目的 | 警察の目的 |
| 場所又は区間 | 警察の場所又は区間（初期値は現場の場所） |
| 期間 | 「令和○年○月○日○時から令和○年○月○日○時まで」 |
| 方法又は形態 | 警察の方法又は形態 |
| 添付書類 | 警察の添付書類 |

## 9. 共通の決まり

| 項目 | 決まり |
|---|---|
| 和暦 | 令和で表示。既存の関数を使う: 年だけ欲しいとき（「令和　年」の枠）は `lib/closingDay.ts` の `toReiwaYear`、年月日の文字は `lib/joyoStatement.ts` の `toReiwaYmd` |

| 日数 | **初日と末日を含めて数える**（国道の申請 令和7年5月1日〜8月31日＝123日間、宇和島 令和7年10月24日〜令和8年8月23日＝304日間、大洲 令和7年9月15日〜11月13日＝60日間 と一致）。手で上書きできる |
| 面積 | 数量は入力どおり（例 0.9486㎡）。「約○㎡」は整数にする（0.9486 → 約1㎡、伊予市の様式 1.821 → 約2㎡）。切り上げか四捨五入かは §14 で kei に確認。手で直せる |
| ㎡ の字 | PDF の共通部品（`SafeText`・`FitText`）は `㎡` を `m²` に置き換える（`components/pdf/styles.ts` の `sanitizePdfText`）。原本は `㎡`。どちらで出すかは §14 で確認（共通部品の置き換えは他の帳票にも効くので変えない） |
| ○ 囲み | 選んだ文字の周りに楕円を描く（Svg）。選んでいない方は文字だけ |
| 長い文字 | 枠に収まらないときは文字を小さくする（`components/pdf/FitText.tsx` を使えるか確認） |

6. `npx tsc --noEmit` と追加したテストが通る。既存のテストを壊していない。

## 12. コミットの分け方と戻し方

| コミット | 中身 | 戻し方 |

| 2 | API・型・既定値・テスト | `git revert` |
| 3 | 画面（メニュー・一覧・編集） | `git revert` |

- コミットメッセージは日本語で「何を・なぜ」。
- **push はしない。** kei の指示を待つ。push 前に `npx tsc --noEmit`。
