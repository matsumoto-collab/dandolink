# 受注明細書（信用保証協会様式）実装仕様

作成 2026-09-03。元ファイル `C:\Users\yushink\Desktop\受注明細書.xlsx`（読み取り専用・リポジトリには入れない＝顧客名が入っている）。
kei 決定: 提出様式のみ／顧客マスタに入金サイト追加／回ごとに保存／自動候補＋手調整／**権限は admin のみ**。

## 0. 何を作るか（1行）
基準日を選ぶと「請求が終わっていない案件」を自動で並べ、出来高・既受領・入金予定の月割りを画面で直して保存し、
提出済みシートと同じ見た目の **Excel（テンプレ差し替え）** と **PDF（react-pdf・A3横）** を出す。

## 1. 様式（提出済みシート「受注工事明細20260601」の実測）
- A3 横・縮小 61%・枠線非表示・余白 左右0 上0.39in 下0.31in。使用範囲 B1:S71。列幅: B=3.5 C=14.5 D=27.5 E=24.83 F=23.83 G〜J=18.5 K〜S=14.5。行高 20.1pt（1行目のみ10.5）。
- 見出し
  - B1:S4 結合 `受　　注　　明　　細　　書`
  - F5:J5 結合 `（令和8年6月1日現在）` ← 基準日を和暦で
  - B6:E7 結合 `申込人` ＋全角空白（申込人名は空欄運用。指定があれば「申込人　○○」）
  - O7:S7 結合 `（単位　千円）`
  - 8〜9行目: `符号｜契約先(8)/工事名(9)｜契約額｜工事着工日(8)/完成予定日(9)｜現在出来高 ％(G9)/金額(H9)｜既受領金額｜現在出来高に対する　　未受領金額｜入金予定(K8:S8)`
  - K9〜R9 は **数値**（書式 `0"月"`）、S9 は数値（書式 `0"月以降"`）。値は基準月 m から m, m+1, …, m+7, m+8（12 の次は 1）
- 明細: 1案件＝2行、**26枠**（行10〜61）。枠 i(0始まり) の上段 r = 10 + 2i、下段 r+1
  - B{r}: 符号（1〜、B{r}:B{r+1} 結合）
  - C{r}: 契約先（C{r}:D{r} 結合）／ C{r+1}: 工事名（C{r+1}:D{r+1} 結合）
  - E{r}: 契約額（千円・E{r}:E{r+1} 結合）
  - F{r}: 着工 `2026/5`（文字列・年/月）／ F{r+1}: 完成予定 `2026/8`
  - G{r}: 出来高％（0〜1 の数値・書式 `0%`）
  - H{r}: 出来高金額（テンプレは `=E*G` の数式。**数式は消して値を書く**）
  - I{r}: 既受領金額 ／ J{r}: 未受領金額 ／ K{r}〜S{r}: 入金予定（月別・千円）
  - 集約行（小口）: C{r}=`その他仮設工事　4件`、C{r+1}=`50万～100万の工事`。F/G は空欄。E・J・K〜S に金額
- 行62: `計`。E62・I62・J62・K62〜S62 は SUM（**値で書く**）
- 行65/68/70 は銀行側の定型文（`※　符号　　の　　月入金予定である…`／`金融機関名　　担当者名　　印`／`※特定の工事代金を返済財源とした…`）＝テンプレのまま
- 数値書式は `#,##0 ;[Red](#,##0)`。**スタイル（s属性）・結合・列幅・印刷設定はテンプレのまま触らない＝値だけ差し替える**

### 実データから読み取った運用（既定値の根拠）
- **100万円以上は個別行**、未満は 8 区分に集約（下記 §3.3）
- **「未受領金額」列は見出しと違い「契約額 − 出来高金額」で 6 回とも記入** → 既定 `remaining`、切替 `unpaid`（= 出来高金額 − 既受領）
- 入金予定は 組立月 60% ／ 解体月 40%（または 50/50）で振っている案件が多い
- 金額は千円単位（四捨五入）

model Customer {

model OrderBacklogReport {
  id                  String   @id @default(uuid())
  asOfDate            DateTime @db.Date       // 基準日（「令和8年6月1日現在」）
  title               String?                 // 任意の呼び名（例: 2026年6月 ○○銀行）
  applicantName       String?                 // 申込人（空欄＝手書き運用）

  taxMode             String   @default("inclusive") // 'inclusive'=税込 | 'exclusive'=税抜（契約額の出し方）
  notes               String?
  createdById         String?
  createdByName       String?
  createdAt           DateTime @default(now())
  updatedAt           DateTime @updatedAt
  lines               OrderBacklogReportLine[]

  @@index([asOfDate])
  @@schema("public")
}

/// 受注明細書の1案件ぶん。区分集約（その他仮設工事 N件…）は保存せず表示時に計算する
model OrderBacklogReportLine {
  id              String  @id @default(uuid())
  reportId        String
  report          OrderBacklogReport @relation(fields: [reportId], references: [id], onDelete: Cascade)
  sortOrder       Int     @default(0)
  projectMasterId String?           // 論理FK（案件を消しても行は残す）
  customerName    String
  projectName     String
  /// 'temp'=仮設工事 | 'new'=新築工事
  workKind        String  @default("temp")
  /// 'house'=住宅 | 'other'=他
  siteKind        String  @default("other")
  contractAmount  Int     @default(0)   // 円
  startYm         String?               // "2026-05"
  endYm           String?               // "2026-08"
  progressRate    Int     @default(0)   // 0〜100
  receivedAmount  Int     @default(0)   // 円
  /// { "2026-06": 4600000, "2026-07": 2300000, "later": 0 } 円。キーは YYYY-MM か 'later'
  schedule        Json?
  excluded        Boolean @default(false) // 候補から外した（出力に出さない・集約にも入れない）
  isManual        Boolean @default(false) // 検索から手で足した
  note            String?

  @@index([reportId])
  @@index([projectMasterId])
  @@schema("public")
}

## 3. 純粋ロジック `lib/orderBacklog/`（prisma を入れない＝画面・PDF・Excel から import する）
### 3.1 型 `types.ts`
```ts
export type UnreceivedMode = 'remaining' | 'unpaid';
export type TaxMode = 'inclusive' | 'exclusive';
export type WorkKind = 'temp' | 'new';
export type SiteKind = 'house' | 'other';
export type ScheduleMap = Record<string, number>; // 'YYYY-MM' | 'later' → 円
export interface OrderBacklogLineInput { id?: string; projectMasterId: string|null; customerName; projectName; workKind; siteKind; contractAmount; startYm; endYm; progressRate; receivedAmount; schedule: ScheduleMap; excluded; isManual; note?; sortOrder }
export interface OrderBacklogReportInput { asOfDate: 'YYYY-MM-DD'; applicantName; individualThreshold; unreceivedMode; taxMode; ... }
```
### 3.2 判定 `classify.ts`
- `workKindFromConstructionContent(content: string|null): WorkKind` … `'新築' | 'new_construction'` → 'new'、それ以外（改修/renovation/大規模/その他/屋根・壁/仮囲い/null…）→ 'temp'
- `siteKindFromProject({ honorific, name, title }): SiteKind` … honorific が `様邸` → 'house'。**`様` だけでは住宅にしない**（本番は法人現場にも様が付く）。name/title に `邸`・`戸建`・`建売`・`号地`・`の家` があれば 'house'、それ以外 'other'
- `bucketKeyFor(line, threshold): BucketKey | null` … contractAmount ≥ threshold → null（個別行）。500,000 ≤ x < threshold → `${workKind}_${siteKind}_mid`、x < 500,000 → `..._low`（**境界: 499,999→low / 500,000→mid / 999,999→mid / 1,000,000→個別**）
### 3.3 集約 `buckets.ts`
- 8 区分の順番と表示名（この順で出す・**件数0の区分は出さない**）:
  | key | 上段 | 下段 |
  |---|---|---|
  | temp_other_mid | その他仮設工事　N件 | 50万～100万の工事 |
  | temp_other_low | その他仮設工事　N件 | ～50万の工事 |
  | temp_house_mid | その他住宅仮設工事　N件 | 50万～100万の工事 |
  | temp_house_low | その他住宅仮設工事　N件 | ～50万の工事 |
  | new_other_mid | その他新築工事　N件 | 50万～100万の工事 |
  | new_other_low | その他新築工事　N件 | ～50万の工事 |
  | new_house_mid | 他住宅新築工事　N件 | 50万～100万の工事 |
  | new_house_low | 他住宅新築工事　N件 | ～50万の工事 |
- 区分行の契約額・既受領・未受領・月別入金予定＝所属行の合計（円で足してから千円に丸める）。出来高％・着工/完成は空欄
### 3.4 既定値の提案 `propose.ts`（候補生成 API とクライアントの「再計算」で共用）
入力: 案件の配置一覧 `{ date: 'YYYY-MM-DD', constructionType: string|null }[]`（種別は**名前**。IDで来たらAPI側で ConstructionType マスタの名前に解決してから渡す）、顧客の closingDay / paymentDuePreset、契約額、既受領、基準日。
- `isWorkFinished(assignments, asOf)`: 基準日以前の配置が無い → false／基準日より後の配置がある → false／基準日以前に `解体` がある → true／`組立` が一度も無い（単発作業）→ true／組立だけ済んで解体が未定 → **false（足場が立ったまま）**
- `proposeProgressRate(assignments, asOf)`: 基準日以前の配置が無い → 0／`isWorkFinished` → 100／それ以外 → 50（**2026-09-04 改訂**: 以前は「先の予定が無ければ100」だったが、解体未定の足場を終わった扱いにしていたので直した）
- `proposeStartEndYm(assignments)`: 最初の配置日の年月 → startYm、最後の配置日の年月 → endYm（1件しか無ければ endYm=null）
- `dueYmFor(workYmd, closingDay, preset)`: 作業日が締め日以前ならその月、過ぎていれば翌月が締め月（closingDay 0=末締め＝当月）→ `dueDateFromClosing(year, month0, preset ?? 'nextMonthEnd')`（lib/closingDay.ts）の年月
- `proposeSchedule({ contractAmount, receivedAmount, assignments, closingDay, preset, asOf, assemblyShare = 60 })`:
  1. 組立月＝最初の `組立`（無ければ最初の配置）、解体月＝最後の `解体`（無ければ最後の配置。組立と同月・同一なら無し）
  2. 解体月あり → 契約額×60% を 組立月の入金月、残り40% を 解体月の入金月／無し → 100% を 組立月の入金月
  3. 既受領を **早い方から差し引く**（既受領 ≥ 全額なら空）
  4. 入金月が基準月より前 → 基準月に寄せる。基準月+8 以降 → 'later'
  5. 戻り: ScheduleMap（円・整数、端数は最後の口に寄せて合計＝未受領額）
### 3.5 出力用の行組み立て `render.ts`（Excel と PDF が同じものを使う）
- `monthColumns(asOf)`: 9列 `{ key: 'YYYY-MM' | 'later', monthNumber: 1..12, label: '6月' | '2月以降' }`
- `toReiwaAsOfLabel('2026-06-01') → '（令和8年6月1日現在）'`（`toReiwaYear` を流用）
- `yen→千円`: `Math.round(v / 1000)`
- `buildOrderBacklogSheet(report, lines)` → `{ asOfLabel, applicantLabel, columns, rows: RenderRow[], totals }`
  - `RenderRow = { kind: 'project' | 'bucket'; code: number; top: string; bottom: string; contractK; startYm?: '2026/5'; endYm?; progressRate?: 0..1; progressAmountK?; receivedK; unreceivedK; scheduleK: number[9] }`
  - 順序: 個別行（契約額の降順、同額は sortOrder）→ 区分行（§3.3 の順）。`excluded` は除く
  - 出来高金額K = round(契約額K × ％)（Excel の `=E*G` と同じ千円ベース）、未受領K = mode に応じて 契約額K−出来高金額K ／ 出来高金額K−既受領K
  - 入金予定: ScheduleMap → 9列（基準月より前のキーは第1列、範囲外は 'later' 列へ）
  - totals: 各列の**千円の合計**（表示値の合計＝Excel の SUM と一致）
  - 26 枠を超えたら `pages: RenderRow[][]`（26 行ずつ、計は最終ページのみ）
### 3.6 候補の抽出条件（API 側 `lib/orderBacklog/candidates.ts` は prisma を使ってよい・判定部分は純粋関数に分けてテスト）
- 案件 = `ProjectMaster` のうち **配置が1件以上あり、最後の配置日が 基準日−6か月 以降**のもの（古い案件は「案件を追加」から手で足せる）
- 除外（`candidateExclusionReason` に集約・**kei 決定 2026-09-04「入金や工事が終わっている案件・見積のみの案件は入れない」**）:
  | 理由 | 条件 |
  |---|---|
  | no_assignment | 配置が無い＝見積だけの未着手案件 |
  | status | `cancelled`（中止）／`completed`（請求完了で付く） |
  | billing_excluded | `billingDecision='excluded'`（請求対象外） |
  | billed_full | 請求済み判定が `'full'`（`resolveBillingBasis` の基準額（税抜） ≤ `computeInvoicedByProject` の請求済み合計（税抜）） |
  | fully_paid | 契約額 > 0 かつ 既受領 ≥ 契約額 |
  | work_finished | `isWorkFinished`（解体済みで先の予定なし／組立の無い単発作業が全部過去） |
  | no_amount | 基準額が無い（見積も contractAmount も無し）。件数を注意書き「（候補全体）: 契約額が未設定の案件 N 件は…」で出す |
- 手動指定（`projectMasterIds`）のときは除外判定を通さない＝載せるかは人が決めている
- 契約額（円）: `resolveBillingBasis` の amount（税抜）を `taxMode='inclusive'` なら ×1.10 して四捨五入（消費税率は candidates.ts の `ORDER_BACKLOG_TAX_RATE`）
- 本番実測（2026-09-04）: 旧ルール 350 件 → 新ルール **120 件**（工事終了 154・完了 24・請求対象外 8・金額なし 74 が落ちた。残りは全件 active・102 件に先の予定あり・18 件は組立済み解体未定）
- 既受領（円）: その案件に紐づく請求書（`InvoiceProjectMaster` と `Invoice.projectMasterId`）の `InvoicePayment.amount + fee` 合計を、まとめ請求なら明細の案件按分比（`invoicedAmountForProject / subtotal`）で按分
- 並び: 契約額の降順
- 戻り: `{ lines: OrderBacklogLineInput[], warnings: { projectMasterId, message }[] }`（金額未設定・顧客の入金サイト未設定 など）
- `projectMasterIds` を指定されたらフィルタを無視してその案件だけ計算する（手動追加用）
