# 足場図面作図機能 設計書

最終更新: 2026-05-05

## 1. 概要

### 目的
足場屋の現場担当者が手書きで作成している「現場調査ノート」を、DandoLink 上で完全にデジタル化する。
これにより以下を実現する：

- 誰でも読みやすい標準フォーマットで記録できる
- 外周・床面積・足場面積の計算を自動化する
- 案件・見積書と連動して情報の一気通貫を実現する
- 過去案件の参照・再利用が容易になる
- 現場でその場で簡易見積を提示できる

### 対象ユーザー
- **案件担当者**: 現場で測定し、その場で入力（モバイル中心）
- **職長**: 事務所で図面を確認、材料計算の参考にする（PC・タブレット）
- **管理者**: 案件管理画面から図面と見積を紐付け確認（PC）

### スコープ外（将来検討）
- 3D プレビュー
- 材料数の完全自動計算
- DXF / CAD ソフト連携

## 2. 背景と現状の課題

### 現在の業務フロー

1. 現場担当者が現場に行き、ノートに建物の形・寸法を手書きで記録
2. 事務所に戻り、ノートを「正書」（清書）して図面化
3. 図面から外周・足場面積を電卓で計算
4. 計算結果をもとに見積書を作成
5. 職長に図面を渡して材料を計算してもらう

### 課題

- **判読困難**: 手書きの線・数字が読みにくく、職長が間違える
- **二度手間**: 現場記録 → 清書 → 図面 → 計算 → 見積、と工程が多い
- **属人化**: 担当者によって記載形式・計算方法が異なる
- **再利用不能**: 過去の類似案件のデータを参照できない
- **現場で見積れない**: 顧客にその場で概算を提示できない

  - **注意**: この動画アプリは「インスピレーション源」として参考にするのみ。UI/UXは独自に再設計する（§2.5 参照）
- 手書きノート画像: 会話履歴で共有された6枚の写真

  - 清翔興産 八幡浜中（シンプル矩形）
  - 宮本テック 大澤邸（本棟+テラス+出窓）

### 2.5 オリジナリティ・差別化方針

将来的な SaaS 化を視野に入れ、参考にした動画アプリと **明確に異なる UX・機能** を持たせる。

**操作面の差別化:**
- 動画アプリ: 4方向ボタンを点の周囲に配置 + 上部モーダル
- DandoLink: **ドラッグ操作で方向指定 + ボトムシートで距離入力**

**視覚面の差別化:**
| 要素 | 動画アプリ | DandoLink |
|---|---|---|
| 配色 | 青系 | 既存ブランドのティール系 |
| 点 | 円 | 角丸正方形またはクロス十字 |
| 寸法ラベル | 線脇の四角枠 | 線上にスマート表示（背景なし + ティック線） |
| ツールバー | 下部の黒帯にアイコン横並び | 右下 FAB → 放射状展開 |
| モーダル位置 | 上部 | 下部からのボトムシート |

**機能面の差別化（オリジナル価値）:**
- DandoLink との一気通貫連動（案件・顧客・見積・職長配置）
- ピンへの音声・写真・GPS情報添付（Phase 2 以降）
- 複数人同時編集（コラボレーション、Phase 4 以降）

これらにより、動画アプリの単なる模倣ではなく **「施工管理システム DandoLink の一機能」として独自の価値を持つ** 形に仕立てる。

## 3. 機能要件

### Phase 1 - MVP（必須機能）

#### 3.1 自由描画エンジン

| 項目 | 仕様 |
|---|---|
| 開始点配置 | キャンバスタップで開始点を置く |
| 方向選択 | 開始点周りに ↑↓←→ ボタンを表示 |
| 距離入力 | 方向タップで距離入力モーダル |
| プリセット | 1000, 1820, 2000, 3000, 3640, 4000, 5000, 6000, 7280, 9100 (mm) |
| カスタム入力 | 任意の数値を mm 単位で入力可 |
| 連続描画 | 終端点タップで続けて壁を追加 |
| 多角形閉鎖 | 開始点付近に戻ると自動で閉じる |
| 方向 | 上下左右の4方向のみ（斜辺は Phase 4 で検討） |

#### 3.2 操作支援

- **戻るボタン**: 直前の操作を取り消し（履歴最大50回）
- **リセットボタン**: 全消去
- **自動ズーム**: 描画範囲に合わせて表示を調整
- **既存点タップ**: 任意の点を起点に切り替え可能（分岐描画用）

#### 3.3 自動計算

- 外周（m）
- 床面積（㎡）
- 足場掛面積（㎡）= 仮の公式 `(外周 + 補正値) × 軒高`
  - 補正値・軒高は入力フォームから設定可
  - 社内の正式な公式が確定したら反映

#### 3.4 注釈

- **ピン**: 図面上の任意の場所にマーカーを配置
- **メモ**: ピンに自由テキストを紐付け
  - 例: 「ベランダ下足場なし」「スペースキューブ必要」「親綱とプレートアンカーを持参」
- **開口**: 壁の一部を「開口あり」とマーク、寸法を入力可
  - 例: 3.6m 開口、5.4m 開口

#### 3.5 セクション別の高さ

同じ建物内で複数の高さを持つ場合に対応。
- 例: 本棟 H=8.2、増築部 H=9.6
- 区域ごとに高さを個別設定

#### 3.6 メタ情報

- 元請会社名
- 現場名
- 工事内容（屋根 / 壁 / 新築 / その他）
- 担当者（複数指定可）
- 組立予定日
- 注意事項
- 引継ぎ事項
- 着時間
- 車両指定

#### 3.7 案件・見積書との連動

- 案件詳細画面に「現場調査」タブを追加
- そこから「現場調査作成」ボタンで起動
- 保存時に案件と紐付け
- 「この調査から見積作成」ボタンで足場面積を見積書の単価マスター項目に流し込み

### Phase 2 - 重要機能

> 注: 当初検討していた「足場仕様チェックリスト」は既に DandoLink に実装済みのため、本機能には含めない。必要に応じて既存の仕様入力画面と SiteSurvey をリンクで連携する。

#### 3.8 PDF / 画像出力

- 図面 + 寸法 + 注釈 + メタ情報を1枚の PDF に
- 用紙サイズ: A4 縦 / A4 横 / A3 横
- 印刷範囲指定
- 職長への共有用、印刷して持参可能

#### 3.9 ピン拡張（音声・写真・GPS）

差別化機能の一環。ピン1つに対して以下を添付できる：

- **音声メモ**: ブラウザの MediaRecorder API で録音、Supabase Storage に保存
- **写真**: カメラ起動 or ギャラリーから選択、現場写真を添付
- **GPS 位置情報**: 現場到着時に自動取得（Geolocation API）、調査全体の住所として保存

これにより、現場で文字入力が面倒な状況でも素早く情報を残せる。

## 4. UI/UX 仕様

### 4.1 画面構成（モバイル基準）

```
┌────────────────────────────┐
│ 現場図面メモ        [↶] [R] │ ← ヘッダー
├────────────────────────────┤
│ 外周: ◯m   面積: ◯㎡       │ ← 統計バー
├────────────────────────────┤
│                            │
│   描画キャンバス             │
│   （方眼背景・ティール系配色）│
│                            │
│                       ┌──┐ │ ← 右下 FAB
│                       │ + │ │   タップで放射状にツール展開
│                       └──┘ │   （ピン / メモ / 屋根 / 出力）
└────────────────────────────┘
```

### 4.2 描画操作（ハイブリッド方式：ドラッグ + タップ）

ユーザーの好みに応じて2通りの操作を選べる。**両方とも最終ステップは同じボトムシート** で完結し、UI に一貫性を保つ。

#### 4.2.1 ドラッグ式（gestural）

操作フロー：
1. キャンバスをタップ → 開始点を配置
2. 開始点を **指で押さえてドラッグ** → 仮の線（点線）が指に追従して伸びる
3. 動かしている方向に応じて、自動的に **8方向（水平/垂直/45度）にスナップ**
4. 指を離す → 画面下からボトムシートがスライドアップ
5. ボトムシート内に **長さ入力**（プリセット + 数値入力）
6. 「壁を追加」 → 線が確定、終端に新しい点

**向いているユーザー：** スマホ操作に慣れている、現場で素早く描きたい

#### 4.2.2 方向タップ式（discoverable）

操作フロー：
1. キャンバスをタップ → 開始点を配置
2. 開始点を **短くタップ**（ドラッグせず）
3. 下からボトムシートがスライドアップ
4. ボトムシート内に **方向セレクタ**（8方向アイコン）と **長さ入力**
5. 方向タップ → 長さ選択 → 「壁を追加」

**向いているユーザー：** スマホ操作に不慣れ、丁寧に確認しながら進めたい

#### 4.2.3 共通

- 両方式とも開始点付近に戻ると自動閉鎖
- 既存点をタップ or ドラッグで起点切替可能
- ボトムシートの UI は両方式で統一

#### 4.2.4 差別化ポイント

- **「点の周囲に方向ボタンを出さない」** ことで動画アプリと差別化
- ドラッグ → ボトムシート / タップ → ボトムシート、いずれも下から出る統一UI
- 8方向対応（4方向ではない）で表現力向上

### 4.3 視覚デザイン仕様

#### 配色
- 主色: **ティール系**（#0d9488 等、DandoLink 既存ブランドに統一）
- 線の色: ティール系の濃淡
- 開口部: 赤系
- ピン: アクセントカラー
- 注: 動画アプリの青系統 (#185FA5) は使わない

#### 点の表現
- 通常点: **小さなクロス十字（+）または角丸正方形**
- 現在の起点: **実塗り角丸正方形**（少し大きく）
- 注: 動画アプリの円形マーカーは使わない

#### 寸法ラベル
- 線の **真上にスマート表示**（背景塗り潰しなし）
- 短いティック線（線に垂直な短い線）でラベル位置を示唆
- フォント: 細めの数字書体
- 注: 動画アプリの「白背景の四角枠」は使わない

#### ツールバー
- **右下 FAB（フローティングアクションボタン）**
- タップで4方向（または放射状）にツールが展開
- 含まれるツール: ピン / メモ / 屋根設定 / 出力
- 注: 動画アプリの「下部の黒帯ツールバー」は使わない

#### モーダル
- **下部からスライドアップする「ボトムシート」** を採用
- 距離入力もこの形式
- 注: 動画アプリの「上部からの黒モーダル」は使わない

### 4.4 注釈の追加方法
- 右下 FAB 展開 → 「ピン」モードに切替
- キャンバス上の任意の位置をタップ
- ピンが配置され、メモ入力ボトムシート
- ピンタップで編集
- Phase 2 以降: ピンに音声・写真・GPS情報を添付

### 4.5 開口の指定方法
- 描画済みの壁をタップ
- 「この壁に開口を追加」ボタン
- 開口位置（壁端からの距離）と開口幅を入力

### 4.6 メタ情報の入力
- 図面上部のタブ or 別画面で入力
- 案件から起動した場合、元請・現場名等は **自動入力**
- 任意項目はあとで追記可能

### 4.7 案件・他データとの一気通貫（差別化の核）

DandoLink の既存データと連動する独自価値：

| 連動先 | 連動内容 |
|---|---|
| 案件マスター | 案件選択 → 元請・現場名・住所が自動入力 |
| 顧客マスター | 元請選択 → 顧客情報が自動入力 |
| 単価マスター | 計算した足場面積 → 見積書の項目に自動流し込み |
| 職長配置 | 担当職長を選択 → 配置カレンダーと連動 |
| 既存の足場仕様入力 | リンクで遷移、調査と仕様を1画面で参照可能 |

これにより「単独の作図アプリ」ではなく「DandoLink エコシステムの一部」となる。

model SiteSurvey {
  id                String         @id @default(uuid())
  projectMasterId   String?

  @@index([createdAt])

## 6. 技術選定

### 6.1 描画ライブラリ
**react-konva** を採用

- 理由: Canvas ベースで高性能、React と相性良し、ピンチ・ドラッグの実装が容易
- 代替検討: Fabric.js（もう少し低レベル）、SVG 自作（柔軟だが工数大）
- インストール: `npm install konva react-konva`

### 6.2 PDF 生成
既存の **@react-pdf/renderer** を流用

- 見積書 PDF 生成で既に使用中（`components/pdf/EstimatePDF.tsx`）
- 新規ライブラリ追加なし

### 6.3 状態管理
**Zustand** で SiteSurvey 専用ストアを新設

- 既存の calendarSlices と同じパターン
- ファイル予定: `stores/siteSurveySlices/`

### 6.3.1 入力レイヤーとコアエンジンの分離

将来の入力方式変更や追加（音声入力など）に備え、明確にレイヤー分離する：

- **DrawingEngine**: 点・線データの管理、面積/外周計算、SVG への描画
  - API 例: `addWall(direction, length)`, `removeLastWall()`, `closePolygon()`, `getStats()`
- **InputController（複数）**: ユーザー入力を受けて DrawingEngine を呼ぶ
  - `DragInputController`: ドラッグ式（v3 プロトタイプの方式）
  - `TapInputController`: タップ式（ボトムシート内で方向選択）
  - 両方とも DrawingEngine.addWall() を呼ぶだけ

これにより：
- ユーザー設定で操作方式を切替可能
- 将来の入力方式追加が容易
- 入力レイヤーのテストがコア計算と独立

### 6.4 既存システムとの連携

- 案件詳細（`ProjectMasterDetailModal.tsx`）に「現場調査」タブ追加
- 見積作成（`EstimateForm.tsx`）に「調査から取り込み」ボタン追加
- 単価マスターと連動して足場面積を自動入力

## 8. 開発ルール

### 8.1 開発環境
- **ローカル開発を基本**（`npm run dev`）
- 本番（Vercel）にはキリのいいタイミングでのみデプロイ
- Vercel デプロイ料金と Claude Code トークン消費を最小化

### 8.2 ブランチ運用
- `main`: 本番
- `feature/scaffold-drawing-phaseX`: 各 Phase の作業ブランチ
- マージ前に Vercel プレビュー URL で確認

### 8.3 テスト
- 描画ロジックは Jest でユニットテスト
- 計算ロジック（面積・外周）は重点的にテスト（誤差を許容しない）
- E2E は Playwright（既存）

### 8.4 Claude Code 運用
- この設計書を毎回参照させる
- プロンプト先頭に「設計書 docs/SCAFFOLD_DRAWING_SPEC.md の §X.Y を参照」と書く
- 新規セッション時は CLAUDE.md（プロジェクトルート）にも案内

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| 開発期間が長い（5〜8ヶ月） | Phase 1 リリース後に運用フィードバックを取りながら進める |
| ユーザーの要件変化 | プロトタイプを段階的に拡張、仕様凍結を急がない |
| パフォーマンス（複雑な図面） | react-konva のレイヤー分割、不要再描画の抑制 |
| 既存業務フローとの整合 | Phase 1 の早期リリースで現場の反応を確認 |
| データ移行（手書きノート→デジタル） | 過去ノートは紙のまま保管、新規案件のみデジタル化開始 |
| 動画アプリとの類似による IP 問題（SaaS化時） | §2.5 の差別化方針を厳守。実装時にも「動画アプリのスクショと並べて明確に違う」ことを定期確認 |
| ドラッグ操作の実装難度 | Konva の drag 機能 + カスタム軸スナップロジック。プロトタイプで早期検証 |
