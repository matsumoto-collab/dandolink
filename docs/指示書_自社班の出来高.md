# 指示書: 自社班の出来高（職長班 × 月の作業一覧）

作成 2026-09-14。設計 = Fable 5.1、実装 = Opus。kei 決定済み: **外注換算は売上×協力業者率／職長ごと＋「全班」／閲覧は admin と manager だけ**。

## 1. 目的

協力業者出来高（`components/PartnerWorkVolume/`）は「会社 × 月」で、行が「日付・元請会社・現場名・担当者・作業内容・金額」の支払い明細になっている。
同じ形で **自社の職長班が月に行った作業** を 1 行ずつ並べ、各行に次の 3 つの金額を出す。

| 列 | 意味 | 答える問い |
|---|---|---|
| 外注換算 | この作業を協力業者に出していたら払った額 | 内製と外注のどちらが得か |
| 稼ぎ | この日この班が会社に残した額（案件の稼ぎを人工で日割り） | 班の生産性（一人当たりの稼ぎと同じ物差し） |
| 人件費 | 按分後の人件費（上書き反映） | 外注換算との差 = 自社でやった得 |

月合計から次を出す。

```
一人当たりの稼ぎ     = 稼ぎ合計 ÷ 人工合計
人件費1円あたりの稼ぎ = 稼ぎ合計 ÷ 人件費合計
自社でやった得       = 外注換算合計 − 人件費合計
```

締め操作（完了・公開）・行追加・PDF は **付けない**（見るだけの集計）。

## 2. 用語と既存部品

- **班 = 職長** = `ProjectAssignment.assignedEmployeeId`。自社職長 = そのユーザーの role（`.toLowerCase()`）が `partner` でも `partner_member` でもない人。
- **人数・時間・人件費** = 原価エンジン `computeProjectCosts(ids, { withDetail: true })` の `detail.labor`（`LaborCostRow`）をそのまま使う。人数 = `workerCount`（日報から原価計上した実数）、人件費 = `effectiveCost`。協力業者職長の配置には labor 行が無いので自然に除外される。
- **案件の稼ぎ** = `computeValueAdded()`（`lib/valueAdded.ts`）。案件詳細 `/api/project-masters/[id]/profit` と同じ入力で呼ぶ（sales = 請求税抜の按分合計、headcount = 案件全体の labor 行 workerCount 合計、estimateSubtotal、hasManualCost、hasAssignments）。
- **売上の按分** = `invoiceProjectShares`、計上対象ステータス = `SALES_INVOICE_STATUSES`（`lib/profitDashboard.ts`）。`isBackfilled: false` の請求書だけ使う（`labor-productivity` ルートと同じ）。
- **協力業者費の自動計算式** = `lib/subcontractorCostCheck.ts` と `SubcontractorCostSection.tsx handleAutoCalc`：
  `total = revenue × revenueRate / 100`、`組立 = round(total × assemblyRate / 100)`、`解体 = round(total × demolitionRate / 100)`。率は `SystemSettings.subcontractorRevenueRate / subcontractorAssemblyRate / subcontractorDemolitionRate`。
  revenue は案件詳細 profit API の `revenue`（`revenueOverride ?? 請求税抜 ?? 見積税抜 ?? contractAmount`）と同じ順で決める。
- 工事種別は UUID マスタ。「組立」「解体」は **名前で解決**（`constructionType.findMany` → name）。

## 3. API

`GET /api/own-crew-volume?year=2026&month=8&foremanId=<userId|all>`（`foremanId` 省略 = all）

- 認可: `requireManagerOrAbove()`（他ロールは 403）。`Cache-Control: no-store`。`export const dynamic = 'force-dynamic'`。
- 手順:
  1. 月の JST 範囲 `[Date.UTC(y, m-1, 1, -9), Date.UTC(y, m, 1, -9))` で `projectAssignment.findMany`（`isBackfilled: false`）。select: `id, projectMasterId, assignedEmployeeId, date, constructionType, memberCount`。
  2. `assignedEmployeeId` のユーザーを引き、自社職長の配置だけ残す。**職長リスト（セレクタ用）はその月に配置のある自社職長**を displayName の日本語順で返す。
  3. 対象案件 = 残った配置の `projectMasterId` の distinct。`computeProjectCosts(ids, { withDetail: true })`。
  4. 案件メタ: `projectMaster.findMany` select `id, title, name, honorific, customerName, contractAmount, revenueOverride, createdBy, subcontractorCosts { constructionTypeId, amount }`。担当者名 = `extractAssigneeIds(createdBy)[0]` のユーザー displayName。
  5. 売上: 全期間の売上請求書（`status in SALES_INVOICE_STATUSES`, `isBackfilled: false`）を `invoiceProjectShares` で按分し、案件ごとの `invoiceSubtotal` を出す。見積は `estimate.findMany({ projectMasterId in ids })` の `subtotal` 合計。
  6. 設定: `systemSettings.findFirst()`（率）＋ `loadValueAddedSettings()`（稼ぎの判定）。
  7. 純粋関数 `buildOwnCrewVolume()`（§4）に渡して行と合計を作る。
- レスポンス:

```ts
{
  year: number; month: number;
  foremen: { id: string; displayName: string }[];       // その月に配置のある自社職長
  groups: {                                              // foremanId=all なら職長ごと、指定ならその 1 件
    foremanId: string; foremanName: string;
    rows: OwnCrewVolumeRow[];
    totals: OwnCrewVolumeTotals;
  }[];
  totals: OwnCrewVolumeTotals;                           // 表示中の全行
  settings: { revenueRate: number; assemblyRate: number; demolitionRate: number; breakevenPerManday: number | null };
}
```

## 4. 純粋関数 `lib/ownCrewVolume.ts`

原価エンジンの出力と案件メタから行と合計を作る。**Prisma を触らない**（テスト対象）。

### 4-1. 原価エンジンへの追加（`lib/projectCost.ts`・追加のみ）

`LaborCostRow` に次を足す（既存の呼び出しは壊れない）。

```ts
foremanId: string | null;   // a.assignedEmployeeId
memberCount: number;        // a.memberCount ?? 0（手配時の予定人数。日報なし行の参考表示用）
workerIds: string[];        // 実際に計上した作業者 ID（`__fb__:` で始まる合成 ID は除く）
```

`__tests__/lib/projectCost.test.ts` などで labor 行を `toEqual` で固定しているテストがあれば、そのテストに 3 項目を足す。

### 4-2. 行の定義

対象 = 表示月の自社職長の配置 1 件につき labor 行 1 件（labor 行は自社職長の配置なら日報が無くても必ず 1 件ある）。

```ts
interface OwnCrewVolumeRow {
  assignmentId: string;
  date: string;                       // 'YYYY-MM-DD'（labor 行の date）
  foremanId: string; foremanName: string;
  projectMasterId: string; projectTitle: string;   // title（正式名称）。無ければ name+honorific
  customerName: string | null; managerName: string | null;
  constructionTypeName: string | null;
  workerCount: number; memberCount: number; hours: number;
  laborCost: number;                  // effectiveCost
  outsourcingEquivalent: number | null;   // 外注換算。出せないときは null
  earnings: number | null;            // 稼ぎの日割り。出せないときは null
  salesBasis: 'invoice' | 'estimate' | 'contract' | 'override' | 'none';
  flags: ('no_report' | 'unbilled' | 'joyo' | 'outsourcing_heavy' | 'labor_override')[];
}
interface OwnCrewVolumeTotals {
  rowCount: number; manDays: number; hours: number;
  outsourcingEquivalent: number; earnings: number; laborCost: number;
  perManday: number | null;           // earnings ÷ manDays（manDays 0 なら null）
  productivityRatio: number | null;   // earnings ÷ laborCost（laborCost 0 なら null）
  makeVsBuy: number;                  // outsourcingEquivalent − laborCost
}
```

### 4-3. 稼ぎの日割り

- 案件の稼ぎ `V`：
  - 請求がある（`invoiceSubtotal > 0`）→ `computeValueAdded().valueAdded`、`salesBasis = 'invoice'`。
  - 未請求 → 見積ベースの仮の値 `V = trunc(estimatedRevenue − nonLaborCost)`。`estimatedRevenue = revenueOverride ?? (estimateSubtotal > 0 ? estimateSubtotal : contractAmount)`、`nonLaborCost = totalCost − laborCost`。`salesBasis` は 'override' / 'estimate' / 'contract'。どれも 0 なら `'none'` で `earnings = null`。
- 案件の総人数 `H` = その案件の **全期間** の labor 行 `workerCount` 合計（表示月に限らない）。
- 行の稼ぎ = `trunc(V ÷ H × row.workerCount)`。`H = 0` なら null。
- 検算: 案件の全行（全月・全班）の稼ぎを足すと `V` と一致する（切り捨て誤差は行数未満）。テストで確認する。

### 4-4. 外注換算

- 種別ごとの額 `A[type]`：
  - 案件に `subcontractorCosts` の `amount > 0` がその種別にあれば **その額**（登録済みの協力業者費・作業費のみ。運搬費は含めない＝自動計算と同じ範囲）。
  - 無ければ自動計算式で「組立」「解体」だけ出す（§2 の式・revenue は §2 の順で決める）。revenue が 0 なら出せない。
  - 組立・解体以外の種別で登録も無ければ **null**（自動計算の対象外なので 0 と決めつけない）。
- 種別ごとの自社人工 `Ht` = その案件・その種別の **全期間** labor 行 `workerCount` 合計。
- 行の外注換算 = `round(A[type] ÷ Ht × row.workerCount)`。`Ht = 0` または `A[type]` が無ければ null。
- 簡略化（仕様として明記）: 同じ案件・同じ種別を協力業者と自社の両方が行った場合、登録済みの額は自社人工だけで割る。稀なので許容。

### 4-5. フラグ

| flag | 条件 | 画面 |
|---|---|---|
| no_report | `workerCount === 0`（日報が無い、または時間が入っていない） | 人数欄に「日報なし」。memberCount があれば「予定 N 名」を薄く添える |
| unbilled | `salesBasis !== 'invoice'` | 稼ぎ・外注換算を薄い色（text-slate-400）で表示し「未請求」バッジ |
| joyo | `workerIds` に role partner / partner_member のユーザーが含まれる | 「常用含む」バッジ（人数には入る） |
| outsourcing_heavy | 案件の `computeValueAdded().outsourcingHeavy` | 「外注中心」バッジ |
| labor_override | labor 行 `override != null` | 人件費欄に「手動」 |

合計は **null を 0 として足さず、値のある行だけ足す**。`unbilled` の行も合計に入れる（薄い色で「未請求 N 行を含む」と注記）。

### 4-6. 並び

日付昇順 → 職長名 → 現場名。「全班」は職長ごとにグループ化し、グループ内は同じ並び。グループの順は職長名の日本語順。

## 5. 画面

- `contexts/NavigationContext.tsx` の `PageType` に `'own-crew-volume'` を追加。
- `components/MainContent.tsx`: dynamic import、`pageTitleMap['own-crew-volume'] = '自社班の出来高'`、`'partner-work-volume'` が入っている **2 か所の配列**（h-full flex の container 判定）に `'own-crew-volume'` も足す。
- `components/Sidebar.tsx`: 「書類・経理」の `協力業者出来高` の直後に `{ name: '自社班の出来高', page: 'own-crew-volume', requiredRoles: ['admin', 'manager'] }`。accountant は含めない。
- `components/OwnCrewVolume/OwnCrewVolumePage.tsx`（ページ）と `OwnCrewVolumeTable.tsx`（表）。
  - 見出し行は `PartnerWorkVolumePage` の header と同じ作り（h1「自社班の出来高」＋月の前後ボタン＋職長セレクタ）。セレクタの先頭は「全班」（value `all`）で **初期値は全班**。月を変えて選択中の職長がその月にいなければ「全班」に戻す。
  - 列: 日付 / 顧客 / 現場名 / 担当者 / 作業内容 / 人数 / 時間 / 外注換算 / 稼ぎ / 人件費 / 注記。金額は `¥` 付き 3 桁区切り、null は「—」。
  - 「全班」のときは職長ごとに小見出し行（職長名）＋グループ小計行を出す。最後に月合計行。
  - 月合計の下に 3 つの数字（一人当たりの稼ぎ／人件費1円あたりの稼ぎ／自社でやった得）をカードで並べる。`breakevenPerManday` があれば一人当たりの稼ぎに最低ラインとの比較（`lib/valueAdded.ts` の判定色と同じ 良好/注意/要改善）。
  - 各金額列の見出しに `components/ui/InfoTip.tsx` で説明を付ける。文言:
    - 外注換算: 「この作業を協力業者に出していたら払った額。案件登録の協力業者費（予定）があればその額、無ければ 売上（税抜）× 協力業者率 を組立・解体に分けた額を、その種別の自社人工で日割りしています。」
    - 稼ぎ: 「案件の稼ぎ（会社に残るお金）を、その案件の延べ人工で割り、この日の人数を掛けた額。班ごとの合計を全班で足すと案件詳細の稼ぎに一致します。」
    - 自社でやった得: 「外注換算の合計 − 人件費の合計。プラスなら自社でやったほうが安く済んでいます。」
  - 表は `bg-white`、行ホバーは `hover:bg-teal-100`（teal-50 は地と同色で見えない）。ページ側で `p-4` の外枠は付けない（MainContent が付ける）。横幅は表だけ `overflow-x-auto`。
  - ロールが admin / manager 以外なら「権限がありません」を出す（API も 403）。
  - 現場名から案件詳細モーダルを開くのは **Phase 2（任意）**。今回は付けなくてよい。
