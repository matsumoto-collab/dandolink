# 通知ベルのリアルタイム修正（Claude Code 向け作業指示）

作成: 2026-10-03 ／ 依頼者: kei（松本）

## 1. 何が起きているか

- 通知ベル（`components/Notifications/NotificationsInbox.tsx`）は、Supabase Realtime の `postgres_changes` で `Notification` の INSERT を購読している（`filter: userId=eq.<userId>`）
- この購読は**毎回失敗している**。DB のログに `invalid column for filter userId` が1日数百回（10/2 は約680回）
- 原因は、ブラウザ側のロール `anon` に public の表を読む権限が無いこと。Realtime は購読者のロールで列の権限を確かめるため、`anon` には列が1つも見えず、`userId` 列が「無い」と判定される
- いまは 30 秒ごとのポーリングとフォーカス時の再取得で動いている（＝通知ベルの更新は最大 30 秒遅れる）。Web Push は別経路なので影響なし

**権限を与えて直してはいけない。** `anon` に `Notification` の読み取りを許すと、公開キー（ブラウザに入っている）を持つ人なら誰でも Data API から全員の通知を読める。DandoLink のログインは Supabase Auth ではないので、RLS で人を区別することもできない。

## 2. 直し方（決定済み）

DB 側に「`Notification` に行が入ったら、公開トピック `notification-<userId>` へイベント `new` を broadcast する」トリガを張る（`docs/manual-migrations/2026-10-03_notification_broadcast.sql`。DB への適用は kei と Claude（Cowork）が行う。**このリポジトリから本番DBに SQL を流さない**）。

ブラウザ側は、同じトピックの broadcast を聞く形に変える。届く中身は通知の `id` だけ（公開トピックなので本文は載せない）。本文や未読数は、今までどおり自分の API（ログイン済みの人だけが読める）から取る。

## 3. 作業

### 3-1. `components/Notifications/NotificationsInbox.tsx`

- `postgres_changes` の購読（`channel(\`notification-${userId}\`).on('postgres_changes', {... table: 'Notification', filter: ...})`）を、broadcast の購読に置き換える
  ```ts
  channel = supabase
      .channel(`notification-${userId}`)
      .on('broadcast', { event: 'new' }, () => {
          setUnreadCount((c) => c + 1);
          if (open && view === 'list') fetchItems(limit);
      })
      .subscribe();
  ```
- チャンネル名は `notification-${userId}` のまま（DB 側のトピック名と一致させる。変えるときは SQL も一緒に変える）
- 30 秒ごとのポーリングとフォーカス時の再取得は**残す**（切断中の取りこぼしを拾うため）
- コメントを実態に合わせて直す（「Realtime 不達時の即応性確保」→「broadcast を取りこぼしたときの保険」など）

### 3-2. 記録

- `docs/manual-migrations/README.md` の履歴表に、`2026-10-03_notification_broadcast.sql` の行を足す（内容: `Notification` の INSERT を公開トピック `notification-<userId>` に broadcast するトリガ）。同じ表に `2026-10-03_enable_rls_all_public.sql` の行が無ければ「未適用」と書いて足す

### 3-3. やらないこと

- `anon` / `authenticated` への GRANT を足さない
- 他の `postgres_changes` の購読（`hooks/useRealtimeSubscription.ts` を使っている約 12 か所、`useProjects.ts`、`MySchedulePage.tsx`、`useCompany.ts`）には触らない。これらも同じ理由で実際には何も届いていない（Realtime 側で「Error 401: Unauthorized」になる）が、画面は broadcast とポーリングで動いているので、別の作業で扱う
- `prisma/schema.prisma` にトリガや関数は書かない（Prisma の管理外。`docs/manual-migrations/` の慣習どおり）
