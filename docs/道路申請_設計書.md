## 1. 目的（kei の要望）

1. 道路使用許可・道路占用許可などの申請書を DandoLink 上で作れるようにする。
2. 添付する図面は、現場で**手書きしたメモ（図）を AI で読み取って**下書きにする。
3. 図面には**車両の絵やカラーコーンなどを置ける**ようにし、操作感は **JWW のような CAD** にする。
   - 参考に挙がったサイト: CAD素材.com のトラック図面（https://cad-freed-rawingsamples.com/truck/）

### 2.4 図面について分かること

- どの申請先も、**位置図・平面図（保安施設配置図）・断面図**をほぼ必ず求めている。立面図・現況写真も多い。

## 3. 作るものの全体像

```
案件（いまの案件一覧）
   │ 「道路申請を作る」
   ▼
道路申請（1 現場の申請一式）
   ├─ ① 申請先を選ぶ … 警察署＋市（＋通行制限・法定外・国道…）
   │        → 必要な書類と添付書類のチェックリストが出る
   ├─ ② 入力 … 自社情報・案件から自動。足りない欄だけ手で入れる
```

## 5. 申請書（様式）の扱い

### 5.1 様式は「データのまとまり」で整理する

書類は 35 種類近くあるが、入力欄は次のまとまりの組み合わせでほぼ全部まかなえる。

| 記号 | まとまり | 使う書類 |
|---|---|---|
| A | 申請者（自社情報） | 全部 |
| B | 現場・工事（案件） | 全部 |
| C | 期間・時間帯 | 全部 |
| D | 道路（路線名・車道/歩道・舗装・住宅地図ページ） | 警察・占用・通行制限・国道 |
| E | 占用物件（名称・構造・規模・数量）※図面から | 占用・法定外・河川 |
| F | 警察の道路使用（目的・方法又は形態・現場責任者） | 警察 |
| G | 通行制限（区間・延長・程度・迂回路・標識・夜間解除・土日祝） | 通行制限 |
| H | 書類ごとの個別欄（車両・運転者、水路幅、見張員の資格 など） | 個別 |

様式はプログラムの中に「カタログ」として持つ（`lib/roadPermit/forms/` に 1 様式 1 ファイル＋一覧の `index.ts`。どのまとまりを使うか・宛先・添付書類の文言。PDF の部品は `components/pdf/roadPermit/`）。様式が増えてもデータの形は変えずに済む。

### 5.2 出力の方式（**決定: DandoLink で PDF を作る**）

| | **PDF を DandoLink で作る（おすすめ）** | 今の Word/Excel に差し込む |
|---|---|---|
| 見た目 | 今の様式と同じ配置で作り直す | 今のファイルそのもの |
| ○で囲む欄（新規/更新/変更、第32条/第35条、車道/歩道 等） | 自動で丸を描ける | 自動化が難しい（手で丸を付ける） |
| 図面との一体印刷 | 申請書＋誓約書＋図面を 1 つの PDF で印刷できる | 別々に印刷 |
| 出したあとの手直し | DandoLink で直してもう一度出す | Word/Excel で自由に直せる |
| 準備 | 様式ごとに見た目を作り込む（1 様式 数時間） | 古い .doc/.xls を .docx/.xlsx に変換し、差し込み位置を決める。Word 用の部品の追加が必要。図形の多い Excel は保存で壊れることがある |
| 今の仕組みとの相性 | 見積書・請求書と同じ作り（@react-pdf/renderer・NotoSansJP） | 出勤簿などで Excel 差し込みの実績あり |

**おすすめ:** よく使う様式は PDF で作り込む。年に数回しか使わない様式（河川・駅前広場・伊予鉄・列車見張員 など）は、今の Word/Excel を使い続け、DandoLink は「入力済みの値を一覧で表示してコピーしやすくする」だけにする。

**注意:** 作り直した様式で受け付けてもらえるか、各窓口に最初の 1 件で確認する（多くの役所は「様式どおりの内容なら可」だが、念のため）。

### 5.3 自動で入れる値

| 欄 | 取り出し元 |
|---|---|
| 申請者の住所・会社名・代表者・電話・FAX・メール | 自社情報（`CompanyInfo`） |
| 担当者・現場責任者の氏名・携帯 | 道路申請の「既定値」（前回の値を覚える）。携帯番号はユーザー情報に無いため |
| 現場の場所・物件名・元請 | 案件（`ProjectMaster` の location / title / customerName） |
| 期間 | 案件の予定開始日・終了日（`scheduledStartDate` / `scheduledEndDate`）を初期値に |
| 日数・○ヶ月間 | 期間から自動計算 |
| 令和の年 | 日付から自動変換 |
| 占用面積（数量） | 図面から（§6.6） |
| 方法又は形態の文案 | 図面に置いた記号から（§6.7） |
| 車両の種類・番号標（通行禁止道路の許可） | 機材台帳（`VehicleSafetyProfile` の vehicleType / registrationNumber） |

## 6. 作図（JWW 風）

### 6.1 基本の考え方

- 図形は**実寸（mm）**で持つ。画面と印刷は縮尺（S=1/50・1/100・1/200・1/250・1/300）で表示するだけ。JWW と同じ。
- 用紙は A4 横・A3 横（申請先に合わせて選ぶ）。用紙の枠を画面に表示し、その中に描く。
- **主に PC（マウス＋キーボード）で使う前提**。タブレットでは表示と軽い修正まで。
- 描画の部品は、すでに入っている `konva` / `react-konva` を使う（2026-07-03 に撤去した「図面（現場調査）」機能でも使っていた。ズーム・パン・方眼などの部品はその時のコードを git から取り出して参考にできる）。新しい外部部品は入れない。

### 6.2 操作（JWW に合わせる）

| 操作 | 動き |
|---|---|
| 左クリック | 自由な点を指示 |
| 右クリック | 近くの端点・交点を読み取る（JWW の「読取点」） |
| Shift を押しながら | 水平・垂直に固定 |
| 数値入力 | コントロールバーに長さ・角度を打ち込んで確定（例: 長さ 11100） |
| Esc | いまの操作を中止 |
| Ctrl+Z / Ctrl+Y | 戻る／進む |
| ホイール | ズーム（カーソル位置中心）。中ボタンドラッグでパン |
| ステータスバー | 「◆始点を指示してください (L)自由点 (R)読取点」のように次にすることを表示。用紙・縮尺・カーソル座標も表示 |

### 6.3 コマンド（左右のボタン）

- 描く: 線、連続線、矩形、円・円弧、**2線**（道路・歩道・側溝を幅を指定して一度に引く）、中心線、文字、寸法（水平・垂直・斜め・連続）、引出線、塗り（ハッチ）。
- 直す: 消去、複写、移動、回転、反転、伸縮、コーナー、範囲選択、属性変更（線種・色・レイヤ）。
- 記号: 記号パレット（§6.4）から置く。置いたあと回転・向き反転。2 点を指示すると、その線に沿って**等間隔に並べる**（例: カラーコーンを 2,000mm おき。間隔はコントロールバーに数値で入れる）。
- 測る: 距離・面積。

### 6.4 記号（JWW の「図形」にあたるもの）

上から見た形（平面）で、**実寸の大きさ**で置く。凡例（記号の説明表）は図面に自動で入る。

| 分類 | 記号 |
|---|---|
| 保安施設（【国道】工事看板様式図より） | 工事看板・工事看板（歩行者用）・工事予告看板（50m〜500m先）・片側交互通行・車線減少・停止位置・速度を落として下さい・歩行者通路・右/左によって下さい・右折・左折工事中・幅員減少・路肩注意・矢印板・クッションドラム・セーフティコーン・コーンバー・コーンバー照明（ピカピカチューブ）・LED回転灯・回転灯・工事用照明・照明車・標識車・規制車・工事用車両 |
| 人 | 交通誘導員（旗の向きつき）・列車見張員 |
| 囲い・柵 | 単管バリケード・A型バリケード・仮囲い・ガードフェンス |
| 足場まわり | 足場（スパン単位で伸ばせる帯）・朝顔・昇降階段・養生シート・敷鉄板 |
| 車両 | 軽トラック・2t 平ボディ・3t/4t 平ボディ・4t ユニック（アウトリガーの張り出し範囲つき）・乗用車 |
| 道路の付属物 | 電柱・消火栓・マンホール・側溝・横断歩道・停止線・方位記号 |

**車両の絵について（CAD素材.com の規約を確認した結果）:**

- 図面への利用・加工は商用でも可。ただし**会社のテンプレートやシステムに組み込むのは「2次配布」にあたり**、自社サイトへのリンク掲載か、問い合わせでの個別許可が要る。社内での共有も 2 次配布扱い。プログラムでの自動取得は禁止。
- 他社向け販売版（dandolink-saas）に将来持ち込むことは、規約上できない。
- **おすすめ:** 車両は**自作の簡単な平面記号**（運転席と荷台の形、実寸）で作る。寸法は自社の車両の実寸（車検証の長さ・幅）を記号ごとに設定できるようにする。CAD素材.com の絵を使いたい場合は、先に問い合わせて許可を取る（→ §11 Q5）。

### 6.5 レイヤ

| 番号 | 名前 | 中身 |
|---|---|---|
| 0 | 道路・境界 | 車道・歩道・側溝・**官民境界**・道路名 |
| 1 | 建物・敷地 | 建物の外形・敷地境界 |
| 2 | 足場・養生 | 足場・朝顔・仮囲い・**占用範囲** |
| 3 | 保安施設 | コーン・看板・バリケード・誘導員 |
| 4 | 車両 | 作業車 |
| 5 | 寸法・文字 | 寸法・注記・幅員 |
| 6 | 下敷き | 手書きメモの写真（薄く表示。印刷しない） |

レイヤごとに 表示/非表示・ロック・印刷する/しない を切り替える。

### 6.6 占用面積の自動計算

- 「占用範囲」（官民境界より道路側に出ている部分）を**図形として描く**か、足場の帯と官民境界から**自動で求める**。
- 路線ごとに面積を出す（例: 大洲の申請「長浜中村線 3.402㎡／堀之内線 0.993㎡」）。
- 申請書の「規模」「数量」に、計算の式つきで入る（例: 西条の申請「11.1×0.81」「8.991㎡」）。手で上書きもできる。

### 6.7 「方法又は形態」の文案

図面に置いた記号を数えて、警察の申請書の「方法又は形態」の文案を作る。例:「4tユニック車1台駐車・カラーコーン6本設置・交通誘導員1名配置」。そのまま使うか手で直す。

### 6.8 断面図

道路の幅員・歩道幅・側溝・官民境界・足場の幅と高さ・朝顔のはね出しを**数値で入れると自動で描く**（一から描かなくてよい）。描いたあと普通の図形として手直しできる。

### 6.9 印刷・書き出し

| 出力 | 中身 |
|---|---|
| PDF | 平面図（保安施設配置図）・断面図。表題欄（工事名・場所・図面名・縮尺・日付・会社名）と凡例つき。申請書と 1 つにまとめて印刷できる |
| DXF | JWW で開ける形式で書き出し。※JWW で文字化けしないか（文字コード）を最初に確認する |

図面のデータは 1 つの形で持ち、**画面（konva）・PDF（@react-pdf/renderer の Svg）・DXF** の 3 つに同じデータから出す。PDF は画像ではなく線で出す（印刷がきれい）。

## 7. 手書きメモの AI 読み取り

### 7.1 流れ

1. 図面タブで「手書きメモを読み取る」→ スマホで撮った写真（または PDF）を選ぶ。
2. AI（Anthropic API。領収書・請求書の読み取りと同じ仕組み）が写真を読み、**「何が・どこに・何 m で」**を決まった形（JSON）で返す。
3. DandoLink がそれを元に**図形を組み立てる**（道路を引き、官民境界、建物、足場の帯、車両・コーン・誘導員を置く）。
4. 写真を「下敷き」レイヤに薄く重ねて表示。見比べて直す。
5. メモに書いてある路線名・期間・時間なども、申請書の欄に入れる候補として出す（そのまま入れずに、確認してから入れる）。

### 7.2 AI に返させる内容（概要）

| 項目 | 例 |
|---|---|
| 道路 | 路線名、車道幅・歩道幅・側溝、現場から見てどちら側か |
| 官民境界 | 建物・道路との位置関係 |
| 建物 | 外形と寸法（書いてある数字） |
| 足場 | どの面に、長さ・幅（出幅）・境界からのはみ出し |
| 保安施設・車両 | 種類・数・どこの近くか・間隔 |
| 寸法 | メモに書かれた数字と、それがどこの寸法か |
| 方位 | 北の向き |
| 文字 | 現場名・路線名・期間・時間などのメモ書き |
| 読めなかったもの | 読めなかった箇所と理由 |

### 7.3 精度についての考え方

- AI は**数字と「何の隣に何があるか」を読むのは得意**だが、**形の正確な位置を写すのは苦手**。そこで、AI には位置の座標ではなく**寸法と関係**を返させ、図形は DandoLink が寸法から組み立てる。
- 読み取った結果は**下書き**。最後は人が下敷きの写真と見比べて確認する。
- 使う AI のモデルは `lib/anthropic.ts` に定数を足して決める（今の最新を Claude Code が確認する）。
- 試すときは**実際の手書きメモの写真**を使う（kei に 3〜5 枚用意してもらう）。

## 8. データの持ち方（DB）

### 8.1 新しいテーブル（案）

```prisma
/// 道路申請（1 現場の申請一式）。警察・市・通行制限などの書類をまとめて持つ
model RoadPermit {
  id              String    @id @default(uuid())
  projectMasterId String?   // 案件（消されても申請は残す）
  title           String    // 例: 〇〇市〇〇町 足場設置（現場の場所＋目的）
  status          String    @default("draft") // draft | submitted | permitted | completed | canceled
  values          Json      // 入力値（§5.1 のまとまり A〜H）
  documents       Json      // 選んだ様式の一覧と、様式ごとの 提出日・許可日・許可番号・許可期限
  drawing         Json?     // 図面（Phase 2〜）
  sketchFileId    String?   // 手書きメモの写真（Phase 3〜。案件ファイルの id）
  createdBy       String?
  updatedBy       String?
  createdAt       DateTime  @default(now())
  updatedAt       DateTime  @updatedAt
  deletedAt       DateTime?

  projectMaster ProjectMaster? @relation(fields: [projectMasterId], references: [id], onDelete: SetNull)

  @@index([projectMasterId])
  @@index([status])
  @@index([createdAt])
  @@schema("public")
}
```

- 追加だけ。既存のテーブルは変えない（`ProjectMaster` には relation の行が 1 行増えるだけで、列は増えない）。
- マイグレーションは今の作り方どおり `prisma/migrations/<日時>_add_road_permit/migration.sql`（何度流しても同じ結果・最後に RLS を有効にする）。**適用するのは kei**（`prisma migrate deploy`）。順番は「先にマイグレ適用 → 後でコードを push」。

## 12. 注意点

- **AI の読み取りは下書き。** 申請書・図面の最終確認は人がする。
- **様式の受付確認。** 作り直した様式は、最初の 1 件を窓口で確認する。
- **国土地理院の地図**（位置図に使う場合）: 申請書の添付地図なら測量法の承認申請は不要。ただし**出典の記載が必要**（加工した場合はその旨も）。https://www.gsi.go.jp/LAW/2930-qa.html （Q1-3・Q1-15）
- **住宅地図**（ゼンリン等）を位置図に使う場合は、その地図の利用条件に従う（DandoLink は画像を貼るだけ）。
- **dandolink-saas には持ち込まない**（今回の作業では触れない）。
- 外部へのアクセスを足す場合（国土地理院の地図など）は `next.config.js` の CSP にも追加する。
- 新しい外部部品（ライブラリ）は入れない方針。入れる必要が出たら kei の承認を取る。
